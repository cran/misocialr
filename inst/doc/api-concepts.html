Understanding the MI Social API

Introduction

The MI Social API (Matriz de Informação Social) is the service behind the public panels of SAGI, the information office of the Brazilian Ministry of Development and Social Assistance (MDS). It is a thin HTTP layer over an Apache Solr index, and understanding that shapes everything the package does: what a document is, why unpublished months come back as zero, and why every response is checked before it is used.

library(misocialr)

Documents: one municipality, one month

Each Solr document holds every published value for one municipality in one month. A document carries identification fields (codigo_ibge, municipio, anomes_s, regiao…) and one field per published measure. The API has no data dictionary of its own; mds_api_fields() lists, month by month, which fields exist in the documents of one municipality:

fields_recife <- mds_api_fields(2611606)

Fields appear and disappear over time (programmes start, are renamed or stop being published), which is why the result has one row per field x month.

Field names and storage suffixes

The last token of a field name says how the value is stored in Solr, and nothing more:

Suffix Storage
_i integer
_l long integer
_f float
_d double
_s string (never a measure)

mds_fields() and mds_api_fields() expose it as storage_type. The suffix does not say what the value measures: that is the role of the dictionary.

nature_basis says where the classification comes from: "medido" means the monthly series itself was inspected (a running total only grows; a monthly value oscillates and restarts); the other values are inferences from a measured field of the same group or from the label and unit.

Zero is not “missing”

Solr has no notion of “not published yet”: a month that was not published comes back as 0, indistinguishable at the document level from a real zero. The package exposes the distinction through facets — counts of municipalities with a non-zero value per month:

periods_pe <- mds_periods("bpc_ben_i", localities = "PE")
tail(periods_pe, 5)
#> # A tibble: 5 × 3
#>   period n_localities n_nonzero
#>   <chr>         <int>     <int>
#> 1 202608          185       185
#> 2 202609          185         0
#> 3 202610          185         0
#> 4 202611          185         0
#> 5 202612          185         0

A trailing run of months where n_nonzero is 0 is the unpublished tail. mds_drop_unpublished() removes it explicitly — and never removes a non-zero value:

  • reference = "selection" (default) decides from the localities of the query itself, with no extra request;
  • reference = "brazil" decides from the whole country, which preserves legitimate zeros of small selections (a municipality without a CREAS, say);
  • action = "flag" classifies the rows (publication_status, publication_reason, publication_reference) instead of removing them.

This is an inference from the published values, not an official publication date.

How misocialr talks to the API

Every query goes through the same pipeline:

  1. Validation before any request. Locality codes (including the IBGE check digit), periods and field names are checked locally; a text field requested as a measure is an error, not an empty result.
mds_data("bpc_ben_i", periods = 2025, localities = 2611600)
#> Error:
#> ! Wrong check digit in municipality code(s): "2611600".
#> ℹ Did you mean "2611606"?

  1. Queries by POST. With many months, fields and municipality codes, the URL of a GET would exceed the server limit (HTTP 414), so the query goes in the request body.

  2. Paging by cursorMark. Pages are read by the sort key rather than by position, so documents added or removed while reading do not shift the pages. The package still verifies that the total does not change and that no document is read twice.

  3. A response contract. A partial Solr result, a missing docs or facet_counts, a document without municipality or month, a non-scalar or non-finite value, and two different values for the same municipality, month and field are all errors with a class (misocialr_error_response, misocialr_error_conflict, misocialr_error_http, all inheriting from misocialr_error) — never silently incomplete data.

  4. A per-session cache. Only responses that pass the contract are cached. refresh = TRUE re-queries a result, options(misocialr.cache_ttl = ) gives the cache a validity in seconds, and mds_clear_cache() clears everything.

How the functions map to the API

Function API mechanism
mds_data(), theme shortcuts documents, paged by cursorMark
mds_api_fields() documents of one municipality, field inventory
mds_periods() facets: non-zero counts per month
mds_localities() documents of one month, one per municipality
mds_drop_unpublished() facets (with reference = "brazil")
mds_fields(), mds_themes() local dictionary, no request
